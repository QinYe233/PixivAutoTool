# 项目改进清单

此清单基于 2026-10-04 的代码审查。优先级是建议处理顺序；除现有自动测试覆盖的行为外，条目仍需在实际使用环境验证。

## 已处理的问题

### 下载目录主进程校验

现在仅允许保存经目录选择对话框选中的绝对路径，入队目录必须匹配当前保存的目录或默认目录。已保存的目录在重启后继续有效。

涉及：`src/main/index.js` 的 `dialog:chooseDir`、`settings:set`、`download:enqueue`；`src/main/queue.js` 的 `enqueue`。

### 动图大小限制与临时文件写入

压缩包上限为 256 MiB，ZIP 帧声明的解压总量上限为 512 MiB；编码时按帧解压。GIF 先写入 `.part`，完成后替换目标文件。受 GIF 编码器和 ZIP 实现限制，转换仍可能消耗较多内存。

涉及：`src/main/ugoira.js` 的 `fetchBuffer`、`fileMap` 和最终写入。

### 历史写入失败反馈

历史写入失败现在会在队列、前台横幅和后台通知中提示。配置与历史 JSON 使用临时文件替换写入。

涉及：`src/main/job.js` 的历史记录阶段；`src/main/history.js`、`src/main/store.js` 的同步写入。

### 网络请求超时与取消

Pixiv API 请求使用 30 秒超时，图片和动图 ZIP 请求使用 5 分钟超时；取消任务会中止已开始的作品解析、图片和动图 ZIP 请求。代理测试的计时器在成功和失败时都会清理。动图编码属于同步 CPU 工作，仅在帧与帧之间检查取消状态。

涉及：`src/main/pixiv.js` 的 `pixivFetch`、`src/main/downloader.js` 的 `fetch`、`src/main/ugoira.js` 的 `fetchBuffer`、`src/main/net.js` 的 `testProxy`。

## 可增加的功能

1. **跨重启恢复队列**：当前任务仅保存在进程内存中。持久化待处理作品和选项，启动后让用户选择继续或清除；恢复前需重新验证下载目录。
2. **失败明细与单项重试**：目前队列主要显示失败数量，可列出作品 ID、页码和错误原因，支持复制错误及单项重试，便于区分鉴权、限流、磁盘和网络问题。
3. **下载空间预检**：批量任务开始前显示目标盘剩余空间、预计文件数量；对动图至少提示 ZIP 与 GIF 转换会额外占用内存和磁盘。

下一步可优先增加失败明细与单项重试，再考虑跨重启恢复队列。
